# Hướng dẫn cập nhật workflow DSL bằng TypeScript để có type safety

## Mục tiêu

Mục tiêu là cho phép người dùng viết workflow DSL bằng TypeScript với:

- autocomplete khi gõ
- hover thông tin kiểu
- kiểm tra lỗi ngay khi nhập
- đảm bảo các kiểu luôn đồng bộ với task registry

Điều này giúp trải nghiệm viết workflow trở nên an toàn hơn, gần với cách làm việc của VS Code, Monaco hoặc các editor TypeScript khác.

---

## 1. TypeScript Language Service là gì?

TypeScript Language Service không phải là một dịch vụ chạy trên mạng. Nó là một thư viện TypeScript chạy trực tiếp trong ứng dụng client.

Đặc điểm:

- miễn phí
- không cần host
- không cần gọi API
- có thể chạy trong browser
- phù hợp cho Monaco, VS Code Web, StackBlitz

Nó chỉ là một thư viện JavaScript/TypeScript khá lớn, nhưng có thể chạy phía client hoàn toàn.

---

## 2. Mô hình đề xuất cho SymFlow

SymFlow có thể cung cấp cho editor một tập hợp file declaration kiểu .d.ts, rồi nạp vào Monaco như các library đọc-only.

### Ví dụ file kiểu ảo

```ts
// symflow-types.d.ts

declare interface Article {
  title: string;
  body: string;
}

declare interface Summary {
  text: string;
  score: number;
}

declare interface Email {
  subject: string;
  body: string;
}
```

Người dùng không được sửa file này. File này chỉ dùng để cung cấp kiểu cho editor.

Khi editor mở, ta nạp file này vào Monaco bằng `addExtraLib()`.

Sau đó người dùng có thể viết:

```ts
const s: Summary = {
  text: "hello",
  score: 1,
};
```

Hoặc:

```ts
function f(a: Article): Summary {
  return {
    text: a.title,
    score: 1,
  };
}
```

Khi đó TypeScript Language Service sẽ tự động:

- nhận biết `Summary` tồn tại
- hỗ trợ autocomplete
- hỗ trợ hover
- báo lỗi khi dùng tên không tồn tại

## 3. Nguồn dữ liệu cho các type

Các type này không nên do người dùng tự định nghĩa.

Nên lấy từ Task Registry làm nguồn chân lý.

Ví dụ, mỗi task có metadata như:

```json
{
  "name": "summary",
  "output": "Summary"
}
```

Backend hoặc CLI sẽ sinh ra:

```ts
// generated by backend or CLI

declare interface Summary {
  text: string;
  score: number;
}
```

Editor chỉ cần load file này vào Monaco.

Điều này đảm bảo kiểu luôn thống nhất với task thật sự có trong hệ thống.

---

## 4. Không chỉ sinh type, nên sinh luôn API

Một bước tốt hơn là không chỉ sinh kiểu, mà còn sinh API cho từng task.

Ví dụ:

```ts
// symflow-api.d.ts

declare function task<T>(
  name: string,
  input: unknown
): Promise<T>;

declare function summary(article: Article): Promise<Summary>;

declare function sendEmail(email: Email): Promise<void>;
```

Sau đó người dùng có thể viết:

```ts
const article = await fetchArticle();
const result = await summary(article);

await sendEmail({
  subject: "Result",
  body: result.text,
});
```

TypeScript sẽ tự kiểm tra toàn bộ dữ liệu.

---

## 5. Mô hình khuyến nghị cho SymFlow

### Cách làm nên dùng

1. Task Registry là nguồn chân lý.
2. Task Registry sinh ra:
   - `symflow-types.d.ts`
   - `symflow-api.d.ts`
3. Editor nạp hai file này vào Monaco ở dạng read-only.
4. Người dùng chỉ viết workflow bằng API đã được cung cấp.

### Lợi ích

- autocomplete đầy đủ
- type checking tự động
- giảm lỗi do typo
- giảm lỗi về kiểu dữ liệu giữa task
- không cần xây riêng một type checker custom

Đây là mô hình rất gần với cách VS Code cung cấp type cho môi trường Node.js, DOM hoặc các thư viện khác bằng `.d.ts`.

---

## 6. Gợi ý metadata cần thêm cho task registry

Để có thể sinh type và API một cách đầy đủ, nên mở rộng metadata của task với các trường như:

```json
{
  "name": "summary",
  "input": "Article",
  "output": "Summary",
  "description": "Tạo bản tóm tắt từ bài viết"
}
```

Có thể dùng metadata này để tự động tạo:

- interface cho input/output
- signature hàm cho task
- autocomplete tên task
- mô tả hover cho task

---

## 7. Kết luận

Cách làm phù hợp nhất cho SymFlow là:

- dùng Task Registry làm nguồn dữ liệu chuẩn
- sinh ra các file `.d.ts`
- nạp vào editor như declaration read-only
- để người dùng viết workflow bằng các API đã được cung cấp sẵn

Như vậy, người dùng sẽ có trải nghiệm viết workflow giống như viết TypeScript thông thường, nhưng được bảo vệ bởi type system và autocomplete từ hệ thống task của SymFlow.
